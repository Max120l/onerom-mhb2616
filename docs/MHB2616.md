# The Tesla MHB 2616

What is known about this chip, and — since the PMD 85-3 CPU board schematic
(DOSKA CPU, 1 PK 280 77) arrived — what is *measured* about how the machine
uses it. The two are kept separate on purpose: the schematic settles how the
board must behave in this machine, without claiming to be a datasheet for
the silicon.

## Known about the part

- **2048 × 8, 24-pin, 5 V read operation.** Every reference that mentions the
  MHB 2616 places it beside the MHB 2716 as the 2 KB generation of Tesla
  memory parts, used in PMD 85 monitor sockets alongside the Soviet К573РФ5.
- **It is the PROM, 2716 the EPROM.** The x616/x716 naming split (also seen
  as MMN2616/MMN2716 from Microelectronica) is programmable-once versus
  UV-erasable. Surveyed PMD 85-3 units carry 2616s labelled only with paper
  stickers — consistent with factory-programmed OTP parts.
- **Address, data and power pins follow JEDEC 2716.** A0–A10 on pins 1–8,
  19, 22, 23; D0–D7 on 9–17; GND 12, Vcc 24.
- **Timing is generous.** Parts of this class are 350–450 ns; the PMD 85's
  8080 runs at ~2 MHz. Nothing in this project is timing-critical the way
  the 1801RE2's handshake was.

## Measured: the control pins, per the PMD 85-3 schematic

This is where the 2616 parts company with the JEDEC 2716, and it is read
off the schematic rather than inferred:

| pin | 2716 has | PMD 85-3 wires it as |
|-----|----------|----------------------|
| 18 | /CE | **PR** — fed A11 (DS4, DS6) or inverted A11 (DS5, DS7) |
| 20 | /OE | **/CS** — active-low pair select, DS4+DS5 tied, DS6+DS7 tied |
| 21 | Vpp | **+5 V**, strapped to the rail with pin 24 |

So the chip has *two* select inputs where a 2716 has enable+output-enable,
and the machine uses one as a genuine select (/CS, from the address decoder)
and the other as an address bit in select's clothing (PR ← A11). Pin 21
carries nothing.

**On PR's active level.** The schematic draws the bubble on /CS but not on
PR, and the chip-side convention is unknown without a datasheet. It also
does not matter for this firmware: what decides which bank a PR level names
is *which socket* the board sits in (straight A11 into DS4/DS6, inverted
into DS5/DS7) plus which chip of the pair holds which monitor half — and
both are captured together by the `MHB_PR_INVERT` build switch, confirmed
empirically by the checksum test in [PMD85-3.md](PMD85-3.md). If the two
banks of a pair come up swapped, flip that switch; do not reorder images.

**Why 2716 swaps ever worked.** Service lore has MHB 2716s substituted into
these sockets. In this wiring a 2716 sees /CE ← A11-or-its-inverse and
/OE ← the pair select — both active low, both required. That functions
exactly when PR is active low on the 2616 too, which is weak evidence for
active-low PR, and stronger evidence that the socket wiring tolerates
either part. The firmware inherits the same tolerance for free: it gates
on levels, not on names.

**If a real MHB 2616 datasheet surfaces** (Tesla catalogue sheets do
circulate — MHB 4116, MHB 8080A, MHB 1012 are all online), the PR
active-level note above can be settled properly. Likely sources: KONDIK and
soucastka component catalogues, scanned Amatérské radio annuals, SAPI.cz.

## In the PMD 85-3

Four sockets, 8 KB of monitor, one 2 KB window each:

| bank | monitor offset | A12 (pair select) | A11 (PR) |
|------|----------------|-------------------|----------|
| 0 | 0x0000–0x07FF | 0 | 0 |
| 1 | 0x0800–0x0FFF | 0 | 1 |
| 2 | 0x1000–0x17FF | 1 | 0 |
| 3 | 0x1800–0x1FFF | 1 | 1 |

`tools/gen_rom_images.py --monitor` splits a flat 8 KB dump (MAME's
`pmd85-3.bin` shape) in exactly this order. Which *physical pair* (DS4+DS5
or DS6+DS7) is which A12 half, and which chip of a pair is which A11 state,
is a question about the mainboard decoder — settled by checksum, per
[PMD85-3.md](PMD85-3.md). The sockets carry bracketed letters —
DS4 "E", DS5 "D", DS6 "C", DS7 "B" on the real machine (the schematic
prints DS6's as "0", a typo) — a consecutive series that presumably
encodes exactly this; trust the checksum over the letters.
