# The Tesla MHB 2616

What is actually known about this chip, what is inferred, and how to close
the gap. The distinction matters because the firmware's one genuinely
configurable safety behaviour — pin 21 — hangs on the part of this file that
is inference.

## Known

- **2048 × 8, 24-pin, 5 V read operation.** Every reference that mentions the
  MHB 2616 places it beside the MHB 2716 as the 2 KB generation of Tesla
  memory parts (Tesla Rožnov pod Radhoštěm), and the PMD 85 service context
  uses the two interchangeably in the same sockets, alongside the Soviet
  К573РФ5. Interchangeable-in-socket pins the read-mode pinout to JEDEC 2716
  for everything that matters in-circuit: addresses, data, ground, Vcc, /CE
  on 18, A10 on 19, /OE on 20, A9 on 22, A8 on 23.
- **It is the PROM, 2716 the EPROM.** The x616/x716 naming split (also seen
  as MMN2616/MMN2716 from Microelectronica) is programmable-once versus
  UV-erasable. Surveyed PMD 85-3 units carry 2616s labelled only with paper
  stickers — consistent with factory-programmed OTP parts.
- **Timing is generous.** Parts of this class are 350–450 ns; the PMD 85's
  8080 runs at ~2 MHz. Nothing in this project is timing-critical the way
  the 1801RE2's handshake was.

## Inferred, and how to verify

**Pin 21 in read mode.** Three candidate roles:

| role | precedent | consequence for the firmware |
|------|-----------|------------------------------|
| Vpp, tied to Vcc | 2716; TI 2516 | ignore it (default) |
| second select, active low | some 26xx PROMs use 18+21 as dual selects | `MHB_PIN21=LOW` |
| programming-only pin, don't-care in read | common for OTP PROMs | ignore it |

Two of three say ignore, and ignoring a select only ever makes the board
*more* willing to drive — which is why this is the one inference worth five
minutes with a meter before first power-on:

1. Board and chips out, machine off. Continuity from socket pin 21 to pin 24
   (Vcc) and to pin 12 (GND).
2. **Tied to Vcc** → the 2716 arrangement; the default build is correct and
   pin 21 reads constantly high, which is also why `MHB_PIN21=LOW` would be
   a brick in this machine: the board would never serve.
3. **Tied to GND** → don't-care wired down; default build still correct.
4. **Neither** → it is driven. Machine on, scope on pin 21 of a working
   socket: if it strobes with reads, it is a select; note the polarity and
   build with `MHB_PIN21=LOW` (or `HIGH`) accordingly.

The firmware never drives pin 21 under any setting, so the worst a wrong
answer costs is a board that serves when it shouldn't (bus fight, visible
immediately with the selftest image) or never serves (dark LED, equally
visible). Neither failure is subtle, but neither belongs in a machine you
care about — hence measure first.

**If a real MHB 2616 datasheet surfaces** (Tesla's own catalogue sheets do
circulate — the MHB 4116, MHB 8080A and MHB 1012 sheets are all online),
this file and the default should be updated from it. The Czech/Slovak
sources most likely to have it: the KONDIK and soucastka component
catalogues, scanned Amatérské radio annuals, and the SAPI.cz documentation
archive.

## In the PMD 85-3

Four sockets, 8 KB of monitor, one 2 KB window each:

| bank | monitor offset | A12:A11 |
|------|----------------|---------|
| 0 | 0x0000–0x07FF | 00 |
| 1 | 0x0800–0x0FFF | 01 |
| 2 | 0x1000–0x17FF | 10 |
| 3 | 0x1800–0x1FFF | 11 |

`tools/gen_rom_images.py --monitor` splits a flat 8 KB dump (MAME's
`pmd85-3.bin` shape) in exactly this order. Which physical socket is which
bank is a question about the machine, not the chip — see
[PMD85-3.md](PMD85-3.md).
